# 3–5 分钟：任务关系核验与修订调查

适用范围：localhost，显式开启 `--allow-local-task-review`，公开合成来源，离线模型传输。执行人标识是自声明标签；没有登录认证、组织审批或正式业务批准。

正向示例的专用离线 Host（不是通用自然语言模型）可在仓库根目录启动：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
python docs/requirements/task-relation-review-closure/browser/offline_source_host.py work/local-review-demo.sqlite 8792
```

用新数据库演示首次捕获。两份来源及唯一 ID 引用需要事先按实际 UI 导入准备；验收脚本保留了这一步的真实操作，不把准备好的 P4 库充当初始状态。若需要一键复现完整准备和验收，见 [证据索引中的命令](EVIDENCE_INDEX.md#可复现命令)。

## 0:00–0:40 来源与问题

打开 Sources，展示 A.md 和 B.md 的原文、来源版本及 SHA。两份记录包含同一任务的明确引用，以及“原计划被本计划替代”的新旧方向。B 对 A 的引用使用 Product 实际分配的唯一 source ID，精确输入保存在本轮浏览器证据的 `source-inputs.json`。这是一条有意满足现有有限来源合同的合成示例，不代表任意自然语言都能通过。

进入 Ask，选择当前空间记录中的任务，输入：

> 调查星河项目 API-4 的任务延续、计划修订和截止日期变化。

## 0:40–1:35 核对关系

查看两项任务原文，展开 SAME_TASK、REVISES_PLAN 与日期步骤。分别说明模型建议、来源合同核验、已持久化且当前有效的关系证明，以及尚未确认的业务状态。核对支持和反对证据；没有返回反证不等于业务批准。

在人工核验表单填写本地执行人标签与备注，保存声明。展示持久化回执和历史。这条声明记录“我核对过什么”，不能覆盖 UNKNOWN、CONFLICT 或缺失的同一任务前提。

## 1:35–2:35 继续独立核验与重新调查

在日期步骤填写备注，点击 CONTINUE 独立来源核验。Host 重新检查当前空间、来源目录、版本、SHA、任务身份、新旧方向及关系生命周期，只捕获既有合同独立证明的关系，返回真实 COMMITTED 回执。

再次提交同一调查问题。展示 2026-10-14 → 2026-10-18、日历日差 4，以及标记了旧 run ID 的相关核验历史。强调：可比较来源中的计划日期边界，当前正式生效计划仍未被业务批准。

## 2:35–3:20 持久性与撤回

刷新页面，在 Ask 点击“重新核验上次任务调查”，展开历史。撤回个人核验声明后，历史保留撤回事件；独立的来源证明不被撤销。页面刷新和 Host 重启的验收证据分别记录，二者不混同。

## 3:20–4:30 不确定性与失效

展示原青竹离线示例：身份引用和第二个日期证据不足。可以记录“不确定”，但 CONTINUE 仍阻塞，不能据日期不同断言计划已修订。

再展示明确反证或第二个浏览器修改来源的验收截图：旧正向结果清除；新来源若同时支持又否定同一任务，保留 CONFLICT，日期不再计算。来源从空间撤回后，旧引用、备注和结论不能继续用于核验。

收尾说明这条演示验证的是可操作的本地人工核验与来源证明闭环；真实 Provider 质量、组织身份和正式业务审批均未实现或未评估。
