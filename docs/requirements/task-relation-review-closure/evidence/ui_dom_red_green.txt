Security closure added after the first GREEN slice
--------------------------------------------------
The hook now passes invalidateResult: () => invalidateAsk(). A source/catalog/
run invalidation or capability/permission refusal clears the parent ask result
and state before showing a quote-free source failure. A revision CAS conflict
with a fresh available review keeps the current source-bound review panel.
The focused test models a second-tab source mutation, POST 409, and a later
language change; the cleared result state prevents the old quote returning.

Final focused UI slice
----------------------
The review hook captures the answer locale from askLocale(result.query), and
its current-view guard checks that same locale. A Chinese answer therefore
receives the Chinese review panel even when state.language is still English.
History items show their run_id plus a current run or related history marker;
old run receipts remain read-only context and are not rendered as historical
source quotes. Host-disabled review replaces only the review panel, preserving
the ordinary read-only task answer and avoiding a false invalidateAsk(), for
both an available=false response and a 403 Host-disabled fetch error. The
focused DOM test covers these cases and still passes after the patch.

Canonical source/proof projection slice
----------------------------------------
The panel now renders source_verdict (with UNKNOWN fallback) and proof.status
and source_verdict_source as separate labeled diagnostics. Canonical
source_supporting_evidence/source_counter_evidence and source_blockers take
precedence over legacy/model proposal evidence; legacy fields remain a
compatibility fallback when the source projection is absent. A SUPPORTED
source verdict is not labeled as an established relation: the persistent
proof status and the existing business-approval-unconfirmed notice remain
visible independently.
