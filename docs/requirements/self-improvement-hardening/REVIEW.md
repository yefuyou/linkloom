# 独立复审与保留意见

独立 Agent 做了两轮只读源码审查，没有访问 Final public 或 Gold，也没有付费调用。独立数据检查核验96例结构元数据、冻结摘要和能力标签，并发现3处 target span 标注缺陷。作者可见 Gold 的事实已经披露。

主要工程发现及处置：

| 发现 | 处置 |
|---|---|
| Final 后恢复还能生成配置 | 封存候选清单及其SHA，任一Final关闭标记均阻止生成；提交曝光身份防止克隆后冒充新盲测 |
| 缓存提案缺身份/预算校验 | 校验实验、freeze、白名单和剩余额度；一轮总生成候选最多3个 |
| Canary 只看 marker 存在 | 绑定账本 request IDs、原始结果/评分SHA、case/config、batch、费用和≤12请求快照 |
| 中断可能重放真实任务 | attempt/terminal 状态保留，缺封存结果即明确停止，不自动重试 |
| Raw/score/report 可能串实验 | 内容摘要及candidate/partition/freeze链校验；损坏不能接纳 |
| 普通正确答案未要求Read到目标passage | 在正式候选前封存v3评分协议，普通事实同样要求完整目标Read覆盖 |
| V1强制读取策略未真正迁移 | 明确真实路径只有Host查询和自愿建议；live gate保持不具接纳资格 |
| 失败堆栈内存地址造成误归因 | 归一化地址；已有失败变化不能仅凭不同堆栈判作候选因果回归 |
| 档案不完整、路径过长、收集hook错误 | 完整可信快照、短路径及Windows I/O、真实collection测试和内容完整性检查 |

复审提出“Core全绿后才付费”的建议未按字面采用：用户授权的是合成只读诊断，SPEC要求先完成配对回归，没有要求历史测试全部绿才准诊断。实际 paid 阶段只在配对执行完成后开始；Core缺口继续否决接纳，没有被忽略或改成通过。

修复后的主Agent验证：51项专项测试曾全部通过（分批：门槛/Provider31、数据12、回归8）；完整命令的封存恢复成功。正式实验6配置×96例、一次Final、真实Gemini64请求及分层工程对照均有记录。最终补丁由主Agent核验，未再取得一次独立全量“绿灯”审查，因此不声明独立批准。

未解决项：冻结标注3处缺陷；作者与生成器共同的关系DSL假设；source_update与stale注入机制部分重合；控制器跨跳证据消费失配；真实模型产物/协议失败；旧测试依赖未提交运行产物；真实对照仅5完整配对且不是阅读策略等价迁移。它们与生产启用、真实Vault试验、合并和新Final数据资格均需人工审核。

结论是拒绝可靠接纳，不是生产就绪。原始失败、Provider请求/响应/Ledger、初版processed导出与修订导出都保留；修正了dev-011的解释，没有改写Raw、Gold或原始成绩。
