## Root causes and narrow corrections

### UNCERTAIN test identity contract

`InterruptedProvider` sent `source_context={}` for search. Current ToolRuntime
requires the full source identity generated by the trusted Runtime request. The
empty fixture was rejected before verified-read and before the intended unknown
Provider outcome. This was an invalid fake action, not a valid call mishandled
by the product.

The fixture now copies `source_context` from the actual `team_decision_request`
packet, as adjacent current tests already do. No arbitrary SHA/fingerprint is
invented. Existing assertions are retained, with repeated-terminal-poll and
whole-formal-decision-state equality checks added. Parameters 1/3/4 prove:
verified source is readable before interruption; HTTP 503/Provider uncertainty;
no temporal/approved Final; calls stop exactly at `fail_at` even after two more
polls; original reviewed Birchline decision remains unchanged.

No file under `src/linkloom/` is modified in RC2. ToolRuntime, Grounding,
Reviewer, provider permission/SDK rules and production failure semantics remain
identical to RC1.

### Chinese two-hop and HOLD-G instability

The shared **offline test controller**, also injected into the browser demo, had
a hidden 30-second wall-clock check beginning at object construction. Snapshot,
setup, checkpoint, source verification and host scheduling all consumed that
budget. Its `ValidationError` is correctly normalized by Runtime as
MODEL_ADAPTER_FAILED; the demonstration evaluator then labels the absent Final
`refused`, even when the sources would support a conflict/partial result.

Controlled reproduction against the original controller code at RC1, with a
31-second clock at turn three, produces HOLD-G `refused/run_interrupted`,
Runtime failed, MODEL_ADAPTER_FAILED, three model turns and no values. The
before-first-turn unit test also reproduces the same expiry. RC1's exact browser
exception detail was not retained; the timer failure mechanism is reproducible,
but we do not invent a missing historical traceback.

RC2 removes only that fake policy timer. Runtime still caps source investigations
at 12 model turns/requests; direct offline harness retains 20, and the existing
7-turn budget-exhaustion regression remains. There is no unlimited fake action
stream or new production retry. Each query creates its own controller, pending
reads and action list. Chinese two-hop uses the same host TaskPlan, model request,
observations, verified evidence, Reviewer and projection through HTTP and browser.
Successful runs take eight turns, so the list of 12 actions is not exhausted.

HOLD-G is exercised with all three cyclic source-order permutations and simulated
31-second host delay: every result must keep Tess Avery, both opposing leader
sources, `partial`, valid dependencies/citations and `conflicting_evidence`.
The original expected oracle/file is unchanged. This separates time-based fake
failure from conflict detection; no production source ranking or conflict rule
is relaxed.

## Gates and reproduction

Use Python >=3.11, `pip install '.[dev]'`, and BM25. Windows test imports use
`PYTHONPATH=src;.;tests/integration`; Actions uses the corresponding colon paths.

**Core Gate:** the explicit source/identity/permission/grounding, temporal/review,
materialization, feedback-four-state, workspace, discovery, two/three-hop,
conflict and product HTTP suites in `offline-pr.yml`, with
`-m 'not legacy_historical'`, plus JS syntax and DOM regression. Two independent
fresh Actions runners execute the same Core matrix; each builds a wheel, retains
the original safety assertions and uploads JUnit even on failure.

**Legacy Historical Gate (temporal replay):** `pytest -m legacy_historical
tests/unit/test_legacy_temporal_inputs.py
tests/integration/test_product_application_flow.py`. Two identity tests and both
original historical scoring paths are separate from Core. Initial local replay:
**4 passed**, no skips or expected-failure markings, 93.80s.

This pair's recoverability does not repair the entire older repository suite.
RC1's four collection errors still refer to untracked G3/stage-C experiment
scripts. Old P8.5 Gemini tests assume their historical 3.1 model/temperature
contract and conflict with the current fixed 3.8 adapter contract; the RC1
81-fail/40-pass observation remains. Fresh old suites also have undeclared
httpx/pydantic requirements. No production SDK restriction is rewritten to
accommodate those assertions. Neither gate is labelled "full suite green".

Actual fresh-install/Core/Actions and browser results are recorded in the PR
RC2 evidence update after verification. Local JUnit, exact timing records and
browser screenshots are retained under ignored `work/rc2-*`, not published as
real-model evidence. The historical RC1 report remains linked for comparison.

## Review and completion boundary

Independent review must confirm no ToolRuntime, evidence/Grounding, Reviewer or
Provider authorization relaxation; original historical assertions/bytes survive;
and no Recovery files enter the incremental diff. Final readiness advice depends
on the actual new Actions result, not merely local passing tests.

Keep PR #3 Draft throughout this task. Even a passing Core gate is not approval
to merge the large historical integration. No master write, Ready action,
duplicate PR, Release, branch deletion or real-vault mutation is authorized.

product appear randomly broken. RC2 makes those test boundaries explicit while
