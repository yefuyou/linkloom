# LinkLoom：周末面试训练入口

源码基线：Recovery `cd668f36300e5bfae7e8c654a54359dc40627d33`。学习分支 `codex/linkloom-interview-readiness`。RC2 是平行分支，本教材没有合入它。准备日期：2026-10-16（北京时间）。

**一句话定位：LinkLoom 帮团队从会议等来源中恢复当前及历史有效决策，并用受约束 Agent 调查有出处的多跳关系。** Markdown/Obsidian 是来源基础；当前产品重点已经发展到团队决策恢复。

## 90 秒介绍：先理解，再用自己的话讲

团队资料里常混着“已经决定”“有人提议”和“后来更换”。LinkLoom 把来源切成带版本和引用的证据，让抽取模型提出候选，经人审核后进入带生效时间与替代关系的 Decision Memory。查当前供应商这类已审事实，可以直接确定性查询，不必调用模型。

需要调查“一个别名对应的项目由谁负责，负责人向谁汇报”时，系统把受支持的问题编译成有依赖的计划。模型选择 Search 和 Read，Runtime 执行工具、检查预算和来源身份；下一跳实体必须来自上一步已核验关系。最终结果还要通过事实 Grounding 和 Reviewer，网页展示原文、版本及不确定性。

项目由我定义产品方向、执行边界和验收要求，通过 Codex 协作推进开发与失败分析。具体参与经历要按自己的真实记录补充。我能解释和复现当前机制，不把 AI 协作代码都说成自己独立手写。当前是有确定性 Workflow 的受约束 Agent，已做合成数据和少量真实模型实验，尚不能声称通用自主规划或生产级可靠性。

以上技术依据见 [架构](01_ARCHITECTURE.md)、[本次产品三跳实验](02_AGENT_LOOP_LAB.md)、[Memory 与历史证据](03_EVIDENCE_MEMORY_AND_FAILURES.md)。

## 先掌握五个概念

1. **权威性**：来源提到某事、模型相信某事、正式业务决定，是三个不同层次。
2. **TaskPlan**：Host 编译的依赖图，只有根实体和待绑定位置，没有预填下一跳答案。
3. **Agent Loop**：模型提议 → Runtime 执行 → Observation 回灌 → 下一轮。
4. **证据门**：Search Hit 还要 Read；引用 ID 还要证明具体主张受原文支持。
5. **三层记忆**：正式决策、运行证据上下文、经人治理的反馈术语。后两者不自动制造正式事实。

## 两天训练：有效学习约 12.5 小时

每个阶段最后 10–20 分钟做闭卷练习。没有答出就回到对应函数，再讲一次；不要整段背答案。

## 先不学什么

跳过 SDK 全部内部实现、通用多 Agent 框架、GraphRAG、模型训练、旧 benchmark 全目录、未用到的向量模式细节。先看五个入口：`ask`、`start`、`RetrievalAgent.execute`、`SingleAgentModelLoop._run_durable`、`_planned_search_query`；位置均在 01/02。

## 学完如何验收

每次闭卷回答按 0/1/2 分：0=只讲术语或讲错；1=流程对但说不出输入输出；2=能给具体输入→处理→输出→失败位置，并找到一条测试/Trace。完成八项目标：产品价值、架构、Loop、证据、多层 Memory、至少三 Bug、Fake/真实模型边界、失败/取舍。每项至少 1 分，Loop/证据/权限必须 2 分。

**教材与验收题已准备，不代表你已掌握。你的闭卷口述、画图与模拟面试目前全部“未验收”。** 可以把不清楚的一轮或一句话直接拿来追问。

全包证据标记：**A**=本次源码与离线测试/Trace交叉确认；**B**=已提交历史报告，本次未重跑；**C**=设计理由、推断或未来方案。A 不等于真实模型效果或 CI 验收。
