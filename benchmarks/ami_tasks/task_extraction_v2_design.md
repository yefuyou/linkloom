# 会议待办抽取 v2 设计方案

状态：第一期已冻结，全量 pytest 通过；ES2002 既有响应离线验证完成，第二期未实施。2026-10-30。

## 第一期 SPEC 与实施边界（本次授权）

当前以用户最新的两期拆分指令为准，覆盖下文完整设计中更广的范围。第一期只实现可评测抽取器：整场/超限大窗口、Host 配置的适配器输入上限、多段精确引用、截止时间 raw_text/kind（resolved_at 恒为空）、同一次调用输出会后范围和完成状态，以及“已解析负责人相同 + 模型同一交付物标签”的简单合并。默认 legacy；旧请求、哈希、测试与离线演示不改变。

不实施持久化、UI、人工审核绑定或拆分视图；不做时间换算，不增加独立状态模型调用或独立语义去重调用。新逻辑放在独立的 meeting_tasks_v2 模块，Gemini 适配器只增加默认仍为 32 KiB 的可信 Host 参数，评测脚本通过 task_extraction_mode 选择。原始候选和多段证据保留在运行结果内，不写产品数据库。

验收：整场优先且超限不截断发言；每段 EvidenceSpan 都校验位置/原文/哈希/版本；未知负责人不合并；deadline.resolved_at 始终为 null；旧路径请求及哈希保持原样；通用提示词不含开发集专有内容；只读 ES2002 开发数据，禁止读取 ES2003 转录、摘要、标注；新增离线边界测试并通过全量 pytest。只运行一次 ES2002 v2，复用已有 legacy 与基线预测，裁判沿用 DeepSeek 和人工修正规则，总新增调用最多 60 次/$1。两日内未完成则停下汇报。全绿后提交 task-eval，不推送。

实施顺序：输入能力和隔离契约 → 引用/字段/状态/简单合并 → 离线验证与独立审查 → 单次开发集评测 → 全量 pytest → 提交。以下内容仍作为完整两期设计保留，并不授权本次实现第二期。

本文只定义下一步产品改动。第 0 步的评测接线修复和一次 LinkLoom 重跑已经完成；本方案完成后不运行任何评测。这里的“v2”是会议待办流程版本，与已有 `task-field-grounding/v2`、`task-recall/v3` 和 observation ID 版本不同。

## 目标与边界

从一场会议中提出会后仍需完成的工作，保留精确出处、明确负责人和原样截止时间，交给人工确认。跨会议追踪、业务任务身份确认和自动写回不在本次设计范围内。方案使用通用会话结构和证据规则，不依赖 ES2002 的会议 ID、句子、角色名称或 gold；不能把本次分数当作未来 v2 的效果证明。

旧流程保持默认。增加显式配置 `task_extraction_mode=legacy|meeting_v2`，默认 `legacy`，旧调用方不必传新参数。FAKE、REPLAY 与现有离线演示保持旧分支；v2 如需离线演示，使用另一个明确选择的 fixture 和入口，不改旧演示内容、请求、哈希或期望结果。无效模式或缺少 v2 配置直接报配置错误，不自动降级、不偷偷调用模型。

v2 流程：会议原文及可信说话人元数据 → 整场/大窗口候选生成 → 每段引用精确校验 → 负责人、截止时间和会末状态判定 → 语义去重分组 → 人工核对。任何步骤都不能绕过引用校验或把模型判断直接变成权威业务记录。

## 1. 候选生成：扩大上下文，缩小证据

- 优先让模型读完整会议；整场不符合明确配置的字节、上下文或费用限制时，再按完整发言生成大窗口，保留重叠和全局发言 ID。不静默截断正文，不从标注 CSV、AMI 摘要或 gold 取任务。
- 建议 v2 输入上限初值：完整模型可见输入 192 KiB（含提示词与发言映射）；大窗口正文目标 48 KiB。它们是待确认的产品上限，不是对模型容量的声明。实际窗口必须同时满足提供方容量、输出容量和当前请求预算。若完整发言仍超限，返回可见的未覆盖区间。
- 产品目前有三层限制：DiscoveryLimits 的 16,000 字符/24,000 字节硬限制、TaskDiscoveryContext 的相同限制，以及 Gemini 适配器的 32 KiB 输入限制。只改分块数值不能实现整场读取。v2 使用独立的 context/limits，并由可信 Host 配置一个有硬上限的提供方输入能力；旧请求仍严格保持原 32 KiB 限制，不允许模型自己提高上限。
- 模型输出规范化的任务描述和原文证据列表，二者分开；不再强求一条任务描述必须是单段原文中的连续片段。要求列出每个独立交付物，不把“一个发言”当成“一个任务”。
- 保留结构化输出及条数/输出 token 上限。达到输出上限或候选容量时明确标记覆盖不完整；不把空输出或截断当“没有待办”。本轮不设计自动无限续问。
- 每个窗口记录覆盖的原文位置。引用定位到整场原始版本，不以窗口序号生成业务任务身份。后面的会末状态判定可读取整场或相关原文窗口，避免只看到早期承诺、遗漏后面的完成/撤销。

拟改文件：`extraction.py` 增加隔离的 v2 提示词/输出 schema 与入口；新增 `meeting_tasks_v2/discovery.py` 和 `config.py`；`agents/model_adapter.py`、`agents/providers/gemini_api.py` 增加受 Host 控制的可选输入能力；`ui/task_investigation.py` 只负责选择旧/新分支。未选择 v2 时，不增加序列化键或改变旧请求指纹。

测试与演示影响：旧上下文/输入上限、固定请求哈希和 REPLAY 断言保留；新增整场、大窗口、完整发言不截断、覆盖不足、容量/费用停止的离线测试。测试禁用网络，以独立中英文小 fixture 验证，不用 ES2002 句子编写规则或断言。旧离线演示继续走 legacy。

## 2. 多段引用：逐段验证，禁止拼接伪装成原文

新候选使用独立的 `MeetingTaskCandidateV2`，不扩大旧 `TaskObservation.raw_text/provenance` 的单段语义。候选包含 `task`、`owners`、`deadline`、会末状态，以及 `evidence[]`：

| 引用字段 | 含义和约束 |
| --- | --- |
| artifact_id / artifact_version_id / content_hash | 来源及不可变版本；必须属于已授权的当前会议 |
| message_id / speaker_id | 由解析器提供，不信任模型臆造的发言人 |
| char_start / char_end / quote / quote_sha256 | 每段必须满足原文切片逐字等于 quote，哈希、位置、发言边界均一致 |
| supports | work / adoption / owner / deadline / completion，说明这段支持什么 |

多段可以来自相隔较远或不同人的发言；保留时间顺序和所有段。原文中重复出现相同短句时，用版本、发言 ID 和明确位置消歧，不靠“全篇只出现一次”拒绝真实出处。模型只给模糊位置、范围错误或改写引文时，退回人工补证据，不进行模糊修复。

工作、负责人、日期可以分别引用不同发言，但“这些段确实指同一项工作”仍是可检查的模型解释，必须附关联理由并接受人工核对；逐字匹配不能独立证明语义关联。任一必需引用失效则候选不能进入可确认集合；缺少非必需字段证据只把该字段置为未知。来源更新后重新核验全部引用；不能只验证第一段。

拟改文件：新增 `meeting_tasks_v2/models.py`、`validation.py`、`persistence.py`；复用 `artifacts.py` 的 EvidenceSpan/哈希机制，不改旧 span 格式。`ui/task_result.py` 及 `static/product-task-result.js` 增加 v2 版本分支，显示每段出处；`ui/task_review.py` 的 v2 绑定覆盖全部引用。v2 运行结果使用独立版本的 JSON，不把多段结果塞入旧单段 serializer，不要求迁移旧记录或改变旧 ID。

测试与演示影响：新增跨发言、跨窗口、重复短句、Unicode、错误位置、来源版本变化、某段失效和序列化往返测试。旧 `test_task_observation.py`、持久化及 source identity 测试原样保留；旧展示不增加必填字段，旧演示仍逐段显示原样结果。

## 3. 截止时间：原文、类型与换算结果分开

| 字段 | 设计 |
| --- | --- |
| raw_text | 原样保存完整表达，包括 before/by/after 等边界词；无信息为 null |
| kind | ABSOLUTE_DATE / RELATIVE_TIME / EVENT_BASED / UNSPECIFIED |
| precision / relation | 年/月/日/时长等精度，以及 BEFORE / AT / AFTER / APPROXIMATE 等边界语义 |
| evidence_refs | 指向角色明确的截止时间原文，不把会议日期当截止时间 |
| anchor / resolved_at | 有可靠真实时间锚、时区、精度时才给出可验证换算；否则为 null |
| resolution_status | RESOLVED / PARTIAL / UNRESOLVED / CONFLICT，保留原因与备选表达 |

例如，`next meeting` 保留为事件型；`in thirty minutes` 保留为相对时间；`as soon as possible` 保留原文并标为不具备数值时长的相对紧迫性，换算结果为空。`before next meeting` 的 before 不能丢失。仅有月份不补日，仅有月日不补年；原日期无效不自动修正。AMI 接线使用的技术 ISO 锚绝不能用于换算。事件与时长只有被原文明示为同一事件时才可关联；有冲突保留待人工判断。

拟改文件：v2 `models.py` 与 `validation.py`，新增 `meeting_tasks_v2/deadlines.py`；v2 schema 由 `extraction.py` 选择。旧 `task_observation.py` 的日期正则、`deadline_text` 和 `_date_value` 保持不变；UI 的 v2 分支明确显示“原文表达 / 类型 / 可选换算”。

测试与演示影响：增加中英文绝对/相对/事件表达、before/after、缺年、月份、时区、无锚、技术锚、冲突、非截止日期和无效日期测试。旧精确日历 token 测试和旧演示的中文绝对日期结果不变。评测仍优先比较原文时间语义，不能因没有 ISO 换算而把正确事件表达判错。

## 4. 只保留会后尚未完成的工作

区分“这句话当时承诺了工作”与“会议结束时还需要做”。每个候选保留承诺/分工证据，并提出 `scope=AFTER_MEETING|IN_MEETING|UNCERTAIN`、`end_state=PENDING|COMPLETED|CANCELLED|UNCERTAIN` 及对应证据。

默认待办集合只包含明确采用、会后仍待完成的工作。会议中已经完成的演示、重画、白板记录等从待办集合排除，保留排除理由供检查。不能仅用 now、I'll、hopefully 或中文某个词判定；须结合整场上下文、交付物、是否有完成/撤回及会末安排。原定会中完成但明确留到会后的，仍可保留。缺乏证据时不擅自宣称完成，也不冒充明确会后任务，列入“需人工判断”区；被排除/不确定候选不会被悄悄删除。

负责人必须是可定位的具体人、角色或明确团队。第一人称承诺可用该发言的可信 speaker 映射为具体 ID；第二人称需有明确受指派对象，否则未知。原文 I/you 留在证据，不作为最终已解析负责人。跨发言转移字段必须有同任务关联证据，不能按职业常识分配。

拟改文件：新增 `meeting_tasks_v2/status.py`，在 v2 `discovery.py` 中于全场候选生成后执行；`validation.py` 校验状态引用和 owner 绑定；UI v2 分支展示“保留 / 排除 / 需判断”和人工修改入口。旧 `task_discovery_veto.py` 与旧 work_state 语义不变。

测试与演示影响：新增先承诺后完成、先提议后采纳、撤销、转为会后继续、时间词相同但状态相反、未知完成状态、多任务独立状态和代词解析测试。旧演示保留历史 observation，不被新会末过滤器影响。

## 5. 语义去重：相同负责人、同一交付义务，保留全部出处

先按已解析负责人的身份集合缩小比较范围；角色与具体人员只有可信映射一致才视为同一负责人。双方都是未知不能证明负责人相同。再判断动作、对象、范围和交付物是否等价。语义模型可提出合并，但不能凭“话题相近”合并不同子任务；所有合并都进入可拆分的人工确认视图。

合并结果保留规范化任务、成员候选 ID、全部引用、各次原文表述及合并理由。重复出现的相同引用按版本/位置去重，不能丢其他出处。负责人或交付范围冲突时不自动合并；日期冲突保留冲突项，不选一个值覆盖。避免 A≈B、B≈C 就推导 A≈C，合并组需要所有成员相容。窗口重叠的同一原文引用先做确定性去重，再做语义判断。

这是同一会议中候选的展示合并，不改写原始观察，不确认跨会议任务身份，也不生成现有关系系统中的业务等价证明。最终人工可以拆分、修改、拒绝。结果 ID 基于有序成员/证据集合及流程版本稳定生成，来源变化使旧确认失效。

拟改文件：新增 `meeting_tasks_v2/grouping.py`，复用 v2 `models.py`、`persistence.py` 的组成员与证据记录；`extraction.py` 增加隔离的语义分组输出 schema；UI v2 分支展示成员与拆分入口。不修改旧 observation ID、旧确切范围去重及旧 task relation proof 规则。

测试与演示影响：新增改写重复、角色/人名别名、不同负责人、未知负责人、同主题不同交付物、一句多个任务、冲突字段、非传递相似、顺序无关及出处全保留测试；模型桩固定语义提议并单独验证本地边界，不能以桩测试证明真实召回改善。旧演示的任务条数和关系判断不变。

## 接线、文件范围和实施顺序

以上 `extraction.py`、`artifacts.py` 等均位于 `src/linkloom/semantic_ingestion/`；新增 `meeting_tasks_v2/` 也在该目录。提供方文件位于 `src/linkloom/agents/`，UI 文件位于 `src/linkloom/ui/`。这些只是拟改清单，本轮未修改。

1. 配置与模型契约：在 `ui/task_investigation.py` 的 TaskInvestigationModels 增加默认 legacy 的模式和可选 v2 limits；`ui/task_provider.py`、`ui/__main__.py` 传递明确选择。旧调用、无新配置的序列化和请求路径保持原样。v2 数据模型/输出明确版本化，与旧严格 schema 并存。
2. 证据与时间：实现逐段验证、负责人绑定、原样时间和精度规则，先用离线 fixture 验证来源完整性。
3. 生成与筛选：实现完整会议/大窗口候选和会末状态，再实现可解释语义合并；模型请求数和费用仍受明确上限约束，所有模型阶段计入同一轮上限。
4. 人工核对与展示：v2 结果以独立版本运行 JSON 保存，扩展现有本地人工核对入口显示全部证据及合并成员。旧持久化数据不迁移；人工核对仍不等于业务授权。旧 P4/关系消费者没有多段契约前，不把 v2 合并项强行伪装成单段 TaskObservation；本方案范围是候选抽取和核对入口。
5. 最后才适配 `scripts/eval_tasks.py` 的显式 v2 模式，与基线隔离输入，沿用冻结 gold 和经人工修正的评分规则。是否运行、使用哪组数据及预算由用户另行确认；本文不授权未来模型调用。

拟新增测试集中在 `tests/unit/test_meeting_tasks_v2_*.py` 与对应集成测试。已有 `test_task_observation*`、`test_task_field_binding.py`、`test_task_recall_protocol.py`、`test_semantic_ingestion_prompt_contract.py`、`test_task_offline_permissions.py`、`test_ui_demo.py`、task review/HTTP/DOM 测试保持断言，不改为只测新行为。验收要求：全部现有测试通过，原离线演示不联网、原输出及权限边界不变；v2 离线测试覆盖上述每项；请求哈希变化仅出现在明确启用 v2 的运行。

## 设计结论与下一步

第 0 步说明：说话人接线修复改善字段绑定，但没有解决跨发言工作证据、英文相对/事件时间、会末任务范围和语义重复。这些需要新的明确契约，不能通过放松精确引用校验解决。本方案保留旧流程，先独立验证 v2 的多段证据和时间结构，再接候选生成、筛选及人工核对。等待用户确认后才能实施；本轮没有实现这些产品改动，没有进行 v2 评测。
