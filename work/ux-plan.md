# L1 界面统一方案（待确认）

基线：`80ee8deba27403edd0cb2826c12c8a5d2035e306`；分支：`feat/ux`。以用户最新原型、会议 HTML 和最新文字规格为准；当前仅方案，未实施。

### 1. 五视图归类与路由映射
- **架构路由（前端哈希驱动）**：后端仅保留 `/` 与 `/tasks` 路由，严禁新增后端路由。前端统一以 `/`（默认重定向到 `/tasks`）与哈希参数调度五大视图：
  1. **会议**（原“来源”）：`/#meetings`，展示会议卡片、日期、一句话摘要与导入入口。
  2. **会议二级待确认**（原“审核”）：`/#review`，承载决定候选、仅供参考的提议、来源复核及独有的 `meeting_tasks` 待审队列。
  3. **决定**（原“决策记忆”）：`/#decisions`，提供按查询日期的有效决定检索与历史演进。
  4. **提问**（原“Ask”）：`/#ask`，单输入框与问答溯源体系。
  5. **待办**：`/tasks`，支持“看板 / 按负责人”双视图切换。

### 2. 精确文件清单
- **前端静态文件**：`src/linkloom/ui/static/product.html`、`src/linkloom/ui/static/product.css`、`src/linkloom/ui/static/product.js`、`src/linkloom/ui/static/tasks.html`、`src/linkloom/ui/static/tasks.css`、`src/linkloom/ui/static/tasks.js`、`src/linkloom/ui/static/product-task-result.js`、`src/linkloom/ui/static/product-task-review.js`。
- **测试文件**：`tests/ui/` 目录下全部 8 个现有 Node DOM（含 `meeting_v3`）及新增 DOM 测试、Playwright 待办与提问测试用例。

### 3. 布局交互与待办状态流
- **看板三列布局**：
  - **待确认**：候选记录原地展开。字段变化胶囊勾选，基于已有同名任务呈现浅蓝提示（仅呈现文字，不自动选中与合并，无匹配仍可显式选目标）；选目标/字段自动请求预览，成功顶部呈现“查看任务→”且不跳转。
  - **进行中**：展示未完成任务（包含真实枚举 `open`、`in_progress`、`blocked` 并渲染真实徽章）；`done` / `cancelled` 归入按负责人视图查询。
  - **最近变化**：按操作只读分组，展示变更摘要。
- **按负责人视图**：真实分组与详情联动；状态下拉框仅为草稿，变更须显式确认并必填理由；历史记录按 `operation_id` 聚合为单节点并引用成组，撤销一次且支持先预览。表头固定“合并后/撤销后”，只渲染变化字段，不设“应用此值”或差异对比冗余按钮。
- **移动适配（390×844）**：看板三列与负责人双栏转为单列纵向堆叠，内边距收缩，内容宽度严格限制 `100vw`，禁止横向溢出。

### 4. 安全、折叠与交互清理
- **折叠文案规范**：全部 Hash、消息 ID、字符偏移量折叠标题固定为“校验信息”；外层操作表单折叠为“理由与校验”；来源哈希固定为“来源详情”。严禁使用“技术细节/技术详情”。
- **去除与清理**：移除“刷新核对”及导航刷新；移除“刷新对照”，操作后由响应自动局部更新，严禁改名重新对比。网络写请求若超时或结果未知，保留安全提示，禁止自动重发。
- **置信度显示**：仅置信度为 LOW 时显示“低置信度”，其他级别完全不显示徽章。

### 5. 提问问答与术语纠正机制
- **提问结构**：单输入框，支持来源会议胶囊与“将使用N场会议：...”摘要并存（不展示哈希），提供示例问题胶囊。外部 AI 逐次授权勾选框、费用与范围常驻可见且默认未选，严禁折叠进高级选项。
- **高级选项（四项）**：收拢展开“指定决定”、“查询日期”（保持后端 UTC 零点语义不变）、“回答语言”、“调查范围”。
- **回答呈现**：结论 + 解释 + 真实原文（会议名、日期、原句）。“当前有效/已被替代”状态仅依据确认状态展示，未知/冲突/中断等系统提示原样保留。“查看这条待办”仅在确有任务链接时展示。
- **术语纠正流**：仅在回答完成后展示链接；点击在原位展开内联表单（禁止弹窗）；审核人沿用已有 `linkloom.tasks.reviewer`，缺失才提示填入，不重复要求录入纠正人；不得宣称认证身份。纠正提交≠批准，保持已有 pending 确认/拒绝与 approved 撤销之动作分离。

### 6. 验收与执行方案
- **测试验证**：开发阶段仅运行相关单元测试。验收运行全部 8 个现有 Node DOM（含 `meeting_v3`）及新增 DOM 测试；运行 Playwright 验证待办合并/撤销与提问全流程；截取四入口桌面端（1440×1000）与移动端（390×844）校验无溢出。
- **全量回归**：本地全量 pytest 仅限单次执行，命令采用 `Start-Process -WindowStyle Hidden` 后台跑批，标准输出/错误流与 `exit.json` 退出码独立分开，严禁日志管道重定向污染 `exit.json`。
- **交付与合规**：方案确认前保持代码零改动；实施后推送至 `feat/ux` 分支、创建 PR、等待 CI 并汇报 PR 链接，绝不直接合并。


### 7. 原型视觉与通用显示
- **设计规范**：底色 `#eef0f3`，纯白卡片 `#fff`（`border-radius: 12px`，`box-shadow: 0 1px 2px rgba(20,30,50,.08)`，无边框）。正文 `#1c2330`，次字 `#5b6472`，主色 `#2550c8`，浅蓝 `#e6ebf7`，LOW 标签 `#8a4f00`/`#fdf0d9`。字体本地 Noto Sans SC 无衬线回退，h1 28px/900，body 15px/1.55。
- **顶栏容器**：`max-width: 1320px`，`padding: 14px 32px`，`gap: 24px`。导航项圆角 8px，当前项浅蓝底，`padding: 8px 14px`。
- **主内容区**：`padding: 28px 32px 64px`，`gap: 22px`。
- 时间显示本地时间到分钟；会议时间仅日期；日期查询继续沿用现有 UTC 零点规则。
- 原型会议画板容器的 max-width 1320px 为内容宽度，左右各32px；使用 border-box 时外宽对应1384px，桌面1440下内容左边约60px；移动单列。
- 方案参考为用户提供的会议 HTML 与最新页面文字说明；会议ZIP没有待办/提问画板，后两者为按文字补齐的草图。

### 8. 旧审核隐藏清单
- 一级审核入口隐藏，完整流程移入会议的二级待确认；旧独立处理面板收进看板候选卡内。
- 原审核的决定候选、参考提议、来源变化复核及 meeting_tasks 均保留。Ask 的关系本地核验仍保留在回答内。
- 与 /tasks 同名的旧审核记录不凭名称、负责人或相似原文自动隐藏；必须能用现有稳定身份确认重复才去除重复入口。没有身份依据时保留独有审核，不能改接口补字段或替代审核动作。
- 移除预览字段差异、应用此值、刷新核对及导航刷新等重复操作入口；当前基线已不存在的按钮不重复改动。
