# Feature SPEC Template

Create feature specs under `docs/requirements/<feature>/SPEC.md`.

## Title

Use a clear feature name and status: Draft, Review, Approved, Implemented, or Deferred.

## Problem

State the user problem, current pain, and why this belongs in Vault Steward.

## Goals

List concrete outcomes the feature must achieve.

## Non-Goals

List tempting work that must remain out of scope.

## Users and Workflows

Describe who uses the feature and the expected workflow from entry to evidence.

## Inputs

List files, vault paths, settings, CLI arguments, or user confirmations required.

## Outputs

List generated reports, proposals, dry-run plans, logs, or changed files.

## Safety and Permissions

State what the feature may read, what it must not mutate, and which approval gates apply.

## Acceptance Criteria

Use testable bullets. Include required evidence for each criterion.

## Implementation Plan

Link to `implementation_plan.md`. Keep sequencing, ownership, and checkpoints there.

## Tasks

Link to `task.md`. Keep executable work items there.

## Open Questions

List decisions that need human confirmation before Worker implementation.

## Learning Reflection

Record what the Planner learned from the spec step and what future agents should preserve.
